Token Pruning Schedule (7B, 32 layers)
================================================================================

Stage 1: SKIPPED (No THCP)
  - Keep all 576 visual tokens

Stage 2: Progressive Pruning (Front-Heavy Strategy)
  - Layers 0-1 (2 layers): 576 tokens (original)
  - Layers 2-11 (10 layers): 192 tokens (Layer 2: 576 → 192) ← Keep more in front
  - Layers 12-23 (12 layers): 64 tokens (Layer 12: 192 → 64)
  - Layers 24-31 (8 layers): 32 tokens (Layer 24: 64 → 32) ← Aggressive at back

Average visual tokens: 128.00 (exact)
Schedule: [(2, 192), (12, 64), (24, 32)]
Verification: (576×2 + 192×10 + 64×12 + 32×8) / 32 = (1152 + 1920 + 768 + 256) / 32 = 128.00 ✓

Strategy: Front-heavy design keeps more tokens in first ~14 layers for rich semantic info

Ablation Study Context
================================================================================

This experiment isolates the contribution of Stage 2 (Progressive Pruning)
by skipping Stage 1 (THCP) on general visual question answering.

GQA requires diverse capabilities:
  - Object detection and recognition
  - Attribute understanding (color, size, material, etc.)
  - Spatial relationship reasoning
  - Multi-step reasoning chains
  - Scene understanding

Comparison for Table 6:
- S1 Only (THCP):          TBD
- S2 Only (front-heavy):   57.13%
- S1+S2 (STAR-Pro):        TBD

Analysis:
  - S2 Only achieves 57.13% on GQA with front-heavy schedule
  - Strong on object detection (82.13%) and verification (77.80%)
  - Weaker on open-ended queries (42.56%) and relationships (49.62%)
  - Front-heavy schedule preserves object detection capability
  - 128 avg tokens (77.8% reduction) maintains reasonable reasoning ability

Key Challenge: GQA's emphasis on spatial relationships and open-ended queries
               requires rich visual information, which is challenging for
               aggressive pruning without Stage 1's semantic selection.
